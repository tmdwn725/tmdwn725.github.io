**LLM 에이전트 플랫폼 엔지니어.** 에이전트 하나를 만드는 게 아니라, 여러 조직이 각자의 에이전트를 올려 쓰는 밑단을 만듭니다.

## 지금 하는 일

**2026.07 ~ 현재**
그룹 단위 AI 서비스의 메인 채팅 에이전트 전담.

**2025.05 ~ 2026.07**
사내 생성형 AI·에이전트 플랫폼 구축. Agent Builder, 공통 실행 Core, Agent SDK, 게이트웨이.

## 다루는 영역

**에이전트 런타임**
도구 호출 루프, 세션과 메모리, human-in-the-loop 승인. 실행 로직을 공통 Core로 분리해 여러 서비스가 같은 런타임을 쓰도록 만들었습니다.

**게이트웨이**
여러 모델 프로바이더(Azure OpenAI, Bedrock, Vertex AI)를 하나의 API 뒤로 숨기고 키·예산·사용량 집계를 붙입니다. 어떤 조직이 어떤 모델을 얼마나 썼는지는 플랫폼에서 기능만큼 중요합니다.

**SDK와 통합**
다른 팀이 자기 서비스에 에이전트를 붙일 수 있게 하는 계층. MCP 연계, 도구 등록 규약, 외부 커넥터 인증.

**안전장치**
민감정보 필터링, 도구 권한, 외부 접근 제어, 승인 게이트. 사내 데이터를 다루는 에이전트에서는 이게 기능보다 먼저입니다.

**인프라와 운영**
온프렘 추론 서버 운영, 컨테이너 배포, 부하 테스트, 서버 보안 대응. 에이전트 플랫폼은 결국 누군가 굴려야 합니다.

## 이전 경력

**2024.04 ~ 2025.04**
유통 계열사 시스템 개발 및 테스트. 물류 ERP/WMS, 커머스 재고 관리, 간편결제 연계 테스트.

**2020.10 ~ 2024.04**
공공 SI. 법령정보 서비스 운영·개발, 전자정부 프레임워크 기반 시스템 구축.

## 개인 연구

회사 일과 별개로 만들고 굴리는 것들입니다. 이 블로그의 글은 대부분 여기서 나옵니다.

**[bio-hub](https://github.com/tmdwn725/bio-hub)**
바이오 계산 도구 게이트웨이. GPU를 직접 소유하지 않고 등록된 백엔드로 잡을 중계합니다. 도구마다 제각각인 호출 방식을 하나의 잡 API로 묶고 키·비용 집계를 붙였습니다.

**온프렘 추론**
개인 데이터를 외부 API에 보내지 않으려고 GPU 한 대에 vLLM을 올려 개인 비서를 굴리고 있습니다. 대역폭 한계, 오프라인 환경, 모델 교체 문제를 여기서 겪었습니다.
